# 화면 기능의 Oracle 연동 계약 (구현 준비)

상태: 정상 ERD를 기준으로 Oracle 스키마와 아래 API를 구현했습니다.
기존 화면의 전체 처리 흐름을 기준으로 작성했습니다. 기존 Oracle 접속 설정은 유지합니다.

## 화면과 API

| API | 동작 및 접근 범위 |
| --- | --- |
| `GET /api/session` | 현재 로그인 사용자와 CSRF 토큰 조회, 미로그인은 사용자 null |
| `POST /api/auth/signup` | 학생 계정 생성 및 로그인; 요청의 관리자 역할 지정은 허용하지 않음 |
| `POST /api/auth/login` | DB 계정 해시 검증, 세션 ID 교체 |
| `POST /api/auth/logout` | 서버 세션 무효화 |
| `GET /api/resources` | DB에 등록된 장비·시설·구성품·이용 조건 조회 |
| `GET /api/availability` | 예약 시간 및 이용 제한 조회; 타인의 신청자 정보는 노출하지 않음 |
| `GET /api/requests` | 학생은 본인 신청만, 관리자는 전체 신청 조회 |
| `POST /api/requests` | 자원 ID와 이용 조건으로 신청 생성; 번호·소유자·생성 시각·상태는 서버 결정 |
| `POST /api/requests` (`type`으로 구분) | 신청·취소·승인·거절·출고·반납·점검 상태 전이 처리 |
| `GET/POST /api/selection` | 로그인 사용자별 선택 목록 조회·저장 |

`auth-service.js`의 메모리 계정과 `rental-records.js`의 IndexedDB 읽기·쓰기를 API 호출로 교체합니다.
기존 브라우저 시연 기록은 실제 신청으로 자동 가져오지 않습니다. 비로그인 선택 목록은
기존 sessionStorage를 유지할 수 있으며, 로그인 후 선택 목록은 SELECTION_ITEM에 저장합니다.
로그인 복원 후 현재 권한에 맞는 신청을 다시 조회하고 로그아웃 시 개인정보를 화면 상태에서 지웁니다.
이전 계정으로 요청한 비동기 응답이 뒤늦게 도착해 현재 계정의 목록을 덮어쓰지 않도록 합니다.

## 서버가 검증할 상태 전이

| 처리 | 허용 조건 |
| --- | --- |
| 신청 | 학생, 유효한 자원·기간·인원·목적, 최초 상태 pending |
| 취소 | 신청자 본인, pending → cancelled |
| 승인 | 관리자, pending → approved, 같은 자원 예약 중복 재검사 |
| 거절 | 관리자, pending → rejected, 거절 사유 필수 |
| 시설 이용 시작 | 관리자, approved → collected, 기존 이용 미종료 여부 확인 |
| 시설 이용 종료 | 관리자, collected → returned |
| 장비 출고 | 관리자, approved → collected, 본체와 구성품 수량·상태 전체 확인 |
| 반납 신청 | 신청자 본인, 장비 collected → return_requested |
| 반납 검수 | 관리자, return_requested 또는 return_held, 출고 기준과 누적 반환 수량 비교 |
| 추가 반환 | 관리자, return_held, 이번 반환 수량만 누적하고 출고 수량 초과 금지 |
| 점검 필요 등록 | 관리자, 실제 확인 및 사유 필수 |
| 점검 완료 | 관리자, 미반환·반납 보류가 없으며 기본 운영 상태도 이용 가능 |

출고 기준은 보존합니다. 과거 출고의 사후 등록 화면/API는 미구현이며, 추가할 때 실제 출고 시각·등록 시각·등록자를 구분해야 합니다.
반납 완료와 장비 점검 완료는 별개입니다. 검수 회차별 수량·손상·메모와 처리자를 저장합니다.
클라이언트의 actor, 역할, 자원명, 상태, 처리 시각을 신뢰하지 않습니다.

## 동시 처리 및 보안

- 회원 비밀번호는 솔트가 포함된 단방향 비밀번호 해시로 저장합니다.
- 인증은 서버 세션으로 관리하고 상태 변경 요청은 CSRF 검증을 수행합니다.
- 요청 값과 SQL을 분리해 바인딩합니다. DB 접속 비밀정보는 기존 로컬 설정을 사용합니다.
- 동일 자원의 승인·출고·반납은 트랜잭션에서 자원 행을 잠그고 현재 상태를 재검사합니다.
- 항목 버전과 장비 버전을 확인해 오래된 요청을 409로 반환합니다.
- 사용자에게는 필요한 오류만 반환하며 SQL·연결 정보·스택 트레이스는 노출하지 않습니다.
- 조회 응답에서 다른 학생의 개인정보와 신청 상세를 제거합니다. 예약 가능 여부는 별도 공개 응답으로 제공합니다.

## 적용한 스키마

정상 물리 ERD의 26개 테이블·185개 컬럼을 사용합니다. 원래 테이블 이름을 유지하고
별도 이름이 없는 시퀀스는 SEQ_ 규칙으로 17개 추가했습니다.
생성 SQL은 `src/main/resources/db/schema-oracle.sql`에 있습니다.
정상 서버 기동에서는 자동 DDL을 실행하지 않습니다.

## 완료 검증

1. 실제 Oracle 회원가입·로그인·세션 복원 및 비밀번호 원문 미저장.
2. 자원·구성품·예약 조건의 DB 조회와 서버 재기동 후 보존.
3. 신청 생성·조회·취소, 다른 학생의 조회·변경 차단 및 역할 위조 차단.
4. 관리자 승인·거절, 같은 자원·시간의 동시 승인 중 하나만 성공.
5. 출고 기준 보존, 반납 보류·추가 반환 누적, 점검 완료 전 이용 제한.
6. 오래된 버전·잘못된 상태 전이·초과 반환·누락 검수·CSRF 요청 거절.
7. 실제 브라우저에서 학생·관리자 흐름과 새로고침 후 DB 조회 확인.
8. 테스트 계정·데이터는 식별 가능하게 분리하고 기존 사용자 데이터는 변경하지 않음.

Git Commit/Push는 별도 사용자 승인 후 진행합니다.
